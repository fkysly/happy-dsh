# Agent Note：窄框架上展开的侧栏覆盖中栏

Status: implemented

[English](2026-09-26-narrow-sidebar-overlay-drawer.md) | 中文

## 问题

窗口宽度低于 1024px 时，侧栏会自动收起为 56px 控制栏；手动展开后，它会以正常宽度（264～420px，默认 280px）重新作为第一条网格轨道。在手机框架（390px）上，中栏只剩约 110px：中文每行只能显示一个字，会话头部的控件溢出框架并被裁掉，而且选择 Session 后侧栏仍保持打开，所选 Session 依然无法阅读。在这样的框架上，布局没有任何能让侧栏与可用中栏同时存在的形态。[响应式侧栏 note](../architecture/2026-09-07-sidebar-responsive-tab-info.zh.md) 负责右栏的让位规则以及 1024px 及以上时左栏的行为；本 note 只涉及低于该宽度时展开的左侧栏。

## 决定

`ui-layout` 中的 `sidebarOverlaysCenter(viewport, sidebar)` 决定侧栏形态：当框架宽度小于解析后的侧栏宽度加 `CENTER_MIN`（400px）时，展开的侧栏覆盖中栏。在这种形态下，框架设置 `data-sidebar-drawer`，将侧栏轨道宽度置为零，把侧栏绝对定位到全宽中栏上方，并在其下方渲染一层遮罩。抽屉没有拖动手柄。

阈值由两个已有的契约最小值推导，而不是新增断点常量：它正是轨道形态无法同时容纳二者的分界点，因此仍能容纳二者的平板框架保留分栏，存储的侧栏宽度越大，越早切换为抽屉。

抽屉通过 store action `collapseOverlaySidebar` 收起；该 action 只修改窄屏展开覆盖值，且只在覆盖形态成立时生效。遮罩会调用它；主视图保留的 Session 发生变化时，`AppFrame` 也会调用它。这个触发点留在 `ui-layout` 内部：Session 选择归 Session Controller 所有，检测选择结果可以避免在 `ui-sidebar` 的每个导航点都加一次布局调用。

## 考虑过的方案

**固定的移动端断点（例如 640px 或 768px）。** 它会重复 `SIDEBAR_MIN` 与 `CENTER_MIN` 已经表达的信息，并在二者任一变化时与之脱节；推导出的阈值恰好在轨道形态失效时切换。

**由 `ui-sidebar` 在每次行激活时关闭抽屉。** 这样也能覆盖点击当前已显示的 Session 和选择全局面板这两种情况，但会把布局关注点分散到另一个包的各个导航行及其测试中。README 已把剩余未自动关闭的情况记为已知限制。

**在抽屉旁保留控制栏。** 抽屉本来就会盖住控制栏，而控制栏轨道会在遮罩后面白白占用中栏 56px，且没有任何交互。

## 后果

- 能容纳两栏的框架渲染结果与之前完全相同；桌面布局和现有的 1024px 自动收起不变。
- 抽屉脱离网格流，因此打开期间中栏和右栏被固定到第 2、3 条轨道；否则自动布局会把中栏放进宽度为零的第一条轨道。jsdom 不执行布局，这个问题只在 390px 框架的真实浏览器检查中暴露。
- 单元测试覆盖了阈值、store action、抽屉 DOM、遮罩以及切换 Session 时的收起。
